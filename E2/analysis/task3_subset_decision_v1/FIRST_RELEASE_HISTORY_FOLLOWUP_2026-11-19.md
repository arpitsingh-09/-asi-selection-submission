## OpenReview revision-history check

The checkout contains `E2/analysis/openreview_archive_v1/benchmark_records.jsonl` and its summary, recovered from the downloaded ICLR 2026 `papers.jsonl` snapshot. For each target it stores the current title, abstract, `cdate`, `odate`, and `mdate`; it does **not** contain the ordered `NoteEdit` records or historic content revisions. The API documentation exposes note edits at `GET /notes/edits`, filterable by `note.id` and sortable by immutable `tcdate`; it also documents `odate` as the time a note becomes public ([OpenReview API definition](https://docs.openreview.net/reference/api-v2/openapi-definition), [date FAQ](https://docs.openreview.net/getting-started/frequently-asked-questions/how-do-i-locate-the-date-a-submission-is-made-public)).

I attempted a read-only request for a public note at `https://api2.openreview.net/notes?id=3FQV4JHPpY`; the environment returned `URLError: [Errno 8] nodename nor servname provided`. Browser retrieval of the JSON API also returned “not accessible via this tool.” Thus I could not retrieve any of the 28 original note histories, and I will not describe the latest snapshot as an original revision.

For future retrieval, the documented endpoint pattern is `GET https://api2.openreview.net/notes/edits?note.id={forum_id}&sort=tcdate:asc&limit=100`; inspect each returned `NoteEdit` (including its `tcdate`, original note payload and `odate`) for all 28 IDs. The server response must be preserved with retrieval time and hash before using it as evidence.
